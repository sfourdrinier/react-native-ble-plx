# ADR: Electron macOS CoreBluetooth main-process native (GAP-E-MAC-SPEC)

**Status:** Accepted  
**Date:** 2026-07-25  
**Branch:** `4.0`  
**GAP:** GAP-E-MAC-SPEC → NAPI → PORT  

## Context

4.0 GA requires Electron **native main-process** BLE on macOS via CoreBluetooth (not Web Bluetooth in the renderer).  
Official Electron guidance (2025–2026): Swift cannot bind Node-API directly; use **Swift → Objective-C bridge → `node-addon-api` (N-API)** with `node-gyp` / `electron-rebuild`.  
See: [Native Code and Electron: Swift (macOS)](https://www.electronjs.org/docs/latest/tutorial/native-code-and-electron-swift-macos), [Node-API](https://nodejs.org/api/n-api.html).

## Decision

| Layer | Choice |
| ----- | ------ |
| Process | Electron **main** only |
| Radio | CoreBluetooth (`CBCentralManager` / `CBPeripheral`) |
| Native bridge | `node-addon-api` ≥ 8.x + optional Swift radio core via ObjC++ |
| Package path | `native/electron/corebluetooth` |
| JS surface | `createCoreBluetoothBlePort({ requireNative: true })` → `BlePort` |
| Fallback | Fake only when `allowMockFallback` / `requireNative: false` |
| Entitlements | `com.apple.security.device.bluetooth` (+ hardened-runtime JIT for Electron) |

## Explicit non-goals

- Reusing `ios/Owned/OwnedCoreBluetoothAdapter.swift` as an RN TurboModule inside Electron  
- WebBT-in-renderer as “supported Electron”  
- Sharing the RN ObjC++ bridge binary with desktop  

Share **BlePort contracts and GATT policy ideas**, not the RN host binding.

## Architecture

```text
Electron Main
  └── createCoreBluetoothBlePort({ requireNative: true })
        └── native/electron/corebluetooth (Node-API .node)
              └── CoreBluetooth (macOS)
  └── IPC / preload only for renderer UI
Renderer never owns BLE
```

## Packaging notes

- Build: `node-gyp` + `electron-rebuild` against the app’s Electron ABI  
- Link framework: `-framework CoreBluetooth -framework Foundation`  
- Deployment target: macOS 11+ (aligned with current Electron Swift tutorial defaults)  
- Notarization: device.bluetooth entitlement when sandboxed  

## Consequences

- Linux CI continues to use Fake + `requireNative` fail-closed contracts  
- macOS CI should compile the addon (L2); live radio is L4 lab  
- PLATFORMS.md must not claim macOS Electron radio **Y** until L4 lab passes
