# ADR: 4.0 host surfaces + dual binary path (adversarial decision log)

**Status:** Accepted for `4.0.0-alpha`  
**Date:** 2026-07-24  
**Branch:** `4.0`

## Context

Maximize testable ROADMAP.4.0 on Linux (Web/Electron) + multi-OS CI package tests, without false GA claims or fake parity.

## Decisions

### D1 — PortBleManager mirrors RN method names

**Choice:** Shared `PortBleManager` uses the same method names as RN `BleManager` for the central slice (`connectToDevice`, `readCharacteristicForDevice`, `*AsBytes`, etc.).

| Persona | Opinion |
| ------- | ------- |
| A App developer | Same names → one mental model / shared helpers across RN and web. |
| B Perf engineer | Fine; cost is TS layer only; bytes path still skips Base64 when callers use AsBytes on port-native hosts. |
| C Security/privacy | OK if web still forces chooser; method names must not imply continuous scan on web. |
| D Maintainability | One surface to test; risk of “looks like full BleManager” — mitigate with `supports()` and docs. |

**Risk if wrong:** Apps assume full RN API on web (restore, FGS). Mitigation: `supports()`, WEB.md, scan throws.

### D2 — Web primary discovery is `requestDevice`, not `startDeviceScan`

**Choice:** `requestDevice()` is the supported discovery API; `startDeviceScan` rejects with a clear error.

| Persona | Opinion |
| ------- | ------- |
| A App developer | Matches browser reality; less surprise than a fake scan. |
| B Perf engineer | N/A |
| C Security/privacy | User gesture + chooser is the privacy model; faking scan would be hostile. |
| D Maintainability | One code path for WebBT; less polyfill theater. |

**Risk if wrong:** Shared “scan first” samples break on web — document migration.

### D3 — Electron: injectable main port + mock fallback, not WebBT-renderer production

**Choice:** `unified-ble-manager/electron` is main-process-oriented; inject `BlePort` (BlueZ/CoreBluetooth/WinRT later). Default `allowMockFallback` for alpha CI; `{ allowMockFallback: false }` throws without a port.

| Persona | Opinion |
| ------- | ------- |
| A App developer | Can ship UI now with mock; wire BlueZ when ready. |
| B Perf engineer | Main process avoids renderer GC/IPC thrash for high-rate notify (later). |
| C Security/privacy | Keep radio out of untrusted renderer when possible. |
| D Maintainability | Charter forbids WebBT-in-renderer as production Electron path. |

**Risk if wrong:** Teams ship mock in production — docs + `getHostInfo().backend` + false allowMock for release builds.

### D4 — RN dual path: AsBytes/FromBytes wrapping Base64 edge until native bytes land

**Choice:** Parallel methods on RN `BleManager`/`Characteristic` convert at the TS edge via `encoding.ts`. Internal hot path stays Base64 to native for alpha; native bytes later without API change.

| Persona | Opinion |
| ------- | ------- |
| A App developer | Can adopt bytes API now without waiting for Kotlin/Swift rewrite. |
| B Perf engineer | Interim win only for app-side; full win after native bytes. Acceptable for alpha. |
| C Security/privacy | No API dual-meaning; `.value` stays Base64-typed. |
| D Maintainability | Matches locked ROADMAP naming; remove wrapper when native lands. |

**Risk if wrong:** Callers think they already get zero-copy native — document interim encoding.

## Independent multi-agent adversarial panel (summary)

Four personas (app developer, perf, security/privacy, maintainability) reviewed the same decisions. Consensus with this ADR:

| Topic | Panel pick |
| ----- | ---------- |
| Port surface | Thin `BlePort` first; host managers name-share only where semantics match (not full RN clone) |
| Web discovery | `requestDevice` primary; `startDeviceScan` fails honestly |
| Electron Linux | Mock-injectable main + capability gate now; real BlueZ when Port contract green |
| RN dual path | Public `AsBytes`/`FromBytes` via shared encoding wrap first; native bytes later under same names |

Perf caveat recorded: wrap-first is an **API** milestone, not a notify-throughput claim until native/JSI bytes land.

## Consequences

- Tests must drive shipped entry points (`/web`, `/electron`, `BleManager.*AsBytes`).
- PLATFORMS.md / supports() stay fail-closed for unknown capabilities.
- Full GA still requires owned native cores, multi-OS Electron previews, device lab (out of this ADR’s alpha scope).
