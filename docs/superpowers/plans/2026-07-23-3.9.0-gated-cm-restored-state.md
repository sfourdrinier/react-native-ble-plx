> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship additive 3.9.0 APIs: `ConnectionManager.attemptConnectOnce` (externally gated single connect) and `BleManager.getRestoredState` (buffered iOS restore handoff), with zero behavior change for existing dual-option restore callers and for all `connect` / auto-reconnect defaults.

**Tech Stack:** TypeScript `src/`, Jest `__tests__/`, existing `BleError` / `BleErrorCode`, docs under `docs/`, branch `feat/27-gated-cm-restored-state`. Issue: [#27](https://github.com/sfourdrinier/react-native-ble-plx/issues/27).

Public `connect(...)` signature and defaults unchanged. `restoreStateFunction` still receives the same mapped shape and is still called on every RestoreStateEvent when provided. Dual-option constructor (identifier + function) behavior for the callback path is preserved. Identifier-only registration is an **additive** expansion (documented). No new package exports beyond methods on existing classes. Prefer no new `BleErrorCode` (`OperationStartFailed` + clear `reason`).

### D1 — Gated coalesce (strict) — APPROVED

**Why (product):** Original issue AC said coalesce with in-flight `connect`, “consistent with existing semantics.” Joining a *multi-retry* `connect` would make the gated caller observe retry scheduling it explicitly opted out of — breaking “one request in → one attempt out.”

**Decision:** `attemptConnectOnce` may **only** coalesce when  
`existing.pendingPromise && !existing.cancelled && existing.gatedAttempt === true`.

| In-flight | `attemptConnectOnce` |
| --------- | -------------------- |
| None | Start gated attempt (`maxRetries: 1`, `gatedAttempt: true`) |
| Gated pending | Coalesce (same Promise; options of first gated caller win) |
| Non-gated `connect` pending (any `maxRetries`) | **Reject** `OperationStartFailed` — do **not** join multi-retry; do **not** fall through to replace |
| Auto-reconnect enabled (idle or not) | **Reject** `OperationStartFailed` |

**Reverse:** `connect()` while gated pending **may** coalesce onto the gated pending Promise (one native attempt; first caller’s options stand — already `maxRetries: 1`). Joining does not enable auto; `gatedAttempt` stays true until settle so `enableAutoReconnect` still throws.

**Compat:** No change to `connect()` ↔ `connect()` coalesce or auto defaults.

### D2 — `getRestoredState` null matrix — APPROVED

**Runtime API:** `Promise<BleRestoredState | null>` (issue candidate). No multi-variant return type in 3.9.0.

| Situation | Settles | Value | How app distinguishes |
| --------- | ------- | ----- | --------------------- |
| No `restoreStateIdentifier` | Immediate | `null` | App did not pass identifier; no wait |
| Identifier set, event not yet | Wait | — | Pending until first event or destroy |
| First event: native `null` | Yes | `null` | Restoration configured + “restored: nothing” / cold / Android null emit |
| First event: `{ connectedPeripherals: [] }` | Yes | that object | Empty list ≠ `null` (unit-tested) |
| First event: peripherals present | Yes | mapped `Device[]` | Restored devices |
| Subsequent events | Immediate (buffer) | **First** buffered value | Callback still fires every emit with **new** mapping |
| Android + identifier | Yes (native emits null on `createClient`) | usually `null` | Synthetic null; no CB restore |
| tvOS + identifier | May wait until destroy if no emit | destroy → waiter `null` | Doc: do not use restore on tvOS |
| Restoration subspec off (iOS) + identifier | May wait until destroy | destroy → waiter `null` | Doc: install Restoration / plugin flag |
| After `await destroy()` | Immediate | `null` | Manager dead — **not** “OS restored nothing” |

**F2.3 reinterp (approved):** “distinguishable” = (1) whether app configured identifier, (2) `null` vs object vs empty `connectedPeripherals`, (3) platform docs — not a richer status enum.

**Native grounding (verified):** Android `BleModule.createClient` only fires restore callback when identifier ≠ null; `BlePlxModule` sends `RestoreStateEvent` with `null`. Listener **must** register **before** `createClient`.

## Grounded invariants (current code)

1. **`maxRetries`** = total attempts including first. `1` ⇒ one native connect, no retry timer.
2. **`connect` coalesce** mutates `pending.resolve`/`reject` chains (preserve exactly).
3. **`enableAutoReconnect`** re-arms on **any** disconnect including `null` error.
4. **`cancel`** bumps `attemptId`; if `!autoReconnect` deletes device entry.
5. **Restore listener today:** only if both identifier and function set; map then callback.
6. **Android:** `createClient` with non-null identifier emits `RestoreStateEvent` null (see `BleModule.java` / `BlePlxModule`).
7. **`destroy()` is async**; clears `sharedInstance` after `destroyClient`.
8. **Singleton:** first constructor options win; second `new BleManager(opts)` returns shared instance.

  )
} else {

}
